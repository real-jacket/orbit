# UI 精修记录（全 app 一遍过）

这份文档记录 2026-10-28 那次「让整个 app 更简洁优雅」的改动：动了什么、为什么这么动、怎么验证。
设计规范本身写在 `DESIGN.md`（配色、字号、间距、组件规则），产品事实写在 `PRODUCT.md`。三者不重复。

## 1. 问题（截图里能直接看到的）

1. 侧栏 8 个模块各挂一块高饱和渐变图标板，整条侧栏像一排放大的 emoji；主色反而被稀释。
2. 摘要条（summary banner）用 60px 高光图标 + 胶囊行 + 两行长描述，每个页面都在抢注意力。
3. 状态页 9 张卡片同权：每张都有彩色大数字、彩色进度条、技术注解（`IOAccelerator` / `SMC Tp*` / `Go 侧 1.5s 采样`），没有主次。
4. 扫描中的空间分析摆满一屏骨架条，右栏是假的方块骨架；顶部却已经有真实进度。
5. 空态是一个旋转图标 + 实心主按钮，而右上角已经有「开始扫描」，一屏两个主行动。
6. 白名单 18 行每行都挂一个「已隔离保护」胶囊，重复到失去意义。
7. 进程表的「结束进程」是常态红框按钮，一屏七个，红色失去警示作用。
8. 硬编码渐变还散落在 legend、方块图色阶、应用占位图标、体检弹层图标上。

## 2. 改法（按层）

- **设计令牌**：`--radius-lg` 12px、间距只用 4/8/12/16/24、动效只留两组（120ms 状态 / 180ms 位移）与一条 `cubic-bezier(0.16,1,0.3,1)`；数字统一 `tabular-nums`；新增 `--accent-ink`（陶土色上的文字用深墨色，白字对比度不够）。
- **全局层**：选择色、9px 滚动条、`:focus-visible` 焦点环、`prefers-reduced-motion` 降级。
- **侧栏**：图标板退成中性底（`--bg-input` + 发丝边），只有当前模块用 22% 主色底 + 主色边；文字元信息仍然是次要色。
- **摘要条**：图标 60→40px 且改平涂色块，标题 17/800→18/700，描述压到一句，右侧统计数字 23→20px、条 5→4px。
- **空态与加载**：空态图标 22px 半透明、标题降到次要色、主按钮改成文字按钮（`btn-quiet`），一屏只保留一个实心主按钮；扫描中改成一块安静面板（真实计数 + 3px 脉冲条 + 取消），不再摆骨架条；右栏没选中项时给一行说明，不再留一整块空白。
- **状态页**：数字统一用正文墨色，只有越过阈值（如磁盘 ≥85%）才升到琥珀色；去掉四张卡的技术注解与两条无意义 sparkline；sparkline 高 34→22px。
- **方块图**：色阶从 6 段渐变改成 6 个平涂色，选中态从「左侧 3px 色条」改成「主色淡底 + 1px 内描边」。
- **破坏性操作**：进程表「结束进程」默认透明且不透明度 0，行悬停/聚焦才出现，点一次才进入玫瑰色确认态；白名单的「已隔离保护」胶囊换成悬停才出现的「移除」文字按钮。
- **渐变清理**：全文件只剩两处渐变——骨架屏的高光与方块图的斜线纹理，两处都是功能性纹理，不是装饰。

## 3. 验证

- `node --check`（抽取内联脚本）通过；impeccable detector 从 6 条降到 **0 条**（其中三条 `transition: width` 已删除，扫描指示器不再做无限横向位移）。
- 在真实 app 里逐屏截图核对（8 个模块 + 浅色 + 确认弹层 + 命令面板），确认：侧栏中性化、摘要条压平、状态页数字统一、扫描面板替代骨架屏、空态只留一个主行动。
- 设计规则写进 `DESIGN.md`，后续改动按它评审。

## 3.1 第二批（同一轮内）

- 状态色不再用 emoji：构建清理/系统加速的行首「🟢」、体检行的「✅/❌/⏳」、确认弹层的「📂」、菜单栏的「🛜」全部换成 6px 状态点或现有图标，全文件 emoji 计数 = 0。
- 一屏一个实心主按钮：面板页脚与「系统加速」面板头里的重复主按钮降级为次级按钮或删除。
- 系统加速的行内操作改成悬停才出现的「执行 →」，未执行项不再每行挂一个「点击立即优化」胶囊。
- 浅色主题不再靠截图判断：改为在页面内读 `getComputedStyle`，对比深浅两套的面板底色、导航激活色、主按钮、圆角与阴影（`navActive` 在浅色为 `rgba(217,119,87,.15)` + 主色文字，深色面板为 `#171715`）。

## 3.2 方块图交互（按你的截图改的）

原来的三个问题：每个方块悬停都会冒出「进入/访达」两个文字按钮（小方块上按钮被挤成竖排、盖住数据）；大块已经把名字/体积/占比写在脸上了，悬停还弹一层浮层重复同样的信息；浮层会盖住相邻方块。

改法（最终版，按钮留在方块里，按尺寸分档）：

- **静止态就有可见提示**：目录方块右下角常驻一个 13px 的 `›`，悬停/选中时让位给真按钮——用户在静止状态就能看出这些方块可以进入。
- **三档动作密度**：内容盒 ≥ 214px 显示「进入 ›」「访达 ▣」文字按钮；74–214px 收成两个 23×21 的图标按钮；40–74px 只留第一个动作（目录是进入、文件是访达）；< 40px 或高度 < 44px 才整组隐藏。按钮 `white-space: nowrap` + `flex: none`，不会再被挤成竖排。
- **动作只在悬停 / 键盘聚焦 / 选中时出现**，出现时底部数字右移 52–74px，体积与占比不会被压住。
- **悬停详情不推动路径**：预览是一格固定宽度（300px，`visibility` 切换而不是 `display`），并且**在模板里就渲染好**，所以第一次悬停也不会让路径组重新排布；面包屑条改成 `flex-wrap: nowrap` + 固定 34px 高，路径过长时由 `.crumb-left` 自己省略。实测悬停前后 `barH 34 / barW 1206 / leftW 372 / actsX 971` 四个值完全不变（改之前左栏 705 → 385 会跳一次）。
- **悬停详情不再浮动**：原来的浮层会跟着鼠标盖住邻居和邻居的体积；现在改成停靠在面包屑左栏的一行只读信息（`.crumb-preview`），位置固定，只在小方块（`<150px` 宽或 `<70px` 高）上补名字/体积/占比/文件数，大块因为脸上已写全而不重复。
- **标签分层更晚降级**：`受限` 徽标到 104px 宽才退化成小圆点，体积行到 54px 高才隐藏。
- **列表更宽**：左栏 276 → 324px、两栏高度 304 → 336px，并去掉与排序重复的序号（名字不再被挤成「Docume…」）。
- 方块描边 3px → 2px、圆角 10 → 9px，选中态只保留 2px 内描边。

验证（同一份代码上量的）：大块 642×338 → 两个 51×21 文字按钮、标签可见；中块 118×172 → 两个 23×21 图标按钮、标签隐藏；小块 88×70 → `.tt-actions` 为 `display: none`。列表标题 `scrollWidth === clientWidth`（157px，不再截断）。注意容器查询量的是**内容盒**，阈值按 `offsetWidth − 26` 折算，这是第一版把 118px 的中块误判成小块的教训。

## 3.3 应用图标（按你的截图改的）

两个问题：图标外面套了一层「squircle 底板 + 内高光 + 投影」，而且个别应用的图是错的（Adobe Creative Cloud Cleaner Tool 显示成一块空白方块）。

- **真实图标不再套底板**：`img.app-squircle-icon` 改成 `object-fit: contain; background: transparent; border-radius: 0; box-shadow: none;`，直接呈现应用自己的图（macOS 图标自带圆角与透明边）。没有图标的回落方块仍然保留渐变底——那本来就是"缺图"的标记。
- **修掉空白图标**：ICNS 里优先 256/512 的 rep（`ic08 > ic13 > ic09 > ic14 > ic07 > ic10 > ic12 > ic11`），并新增 `pngLooksBlank`：整幅透明、或超过 92% 采样像素同一颜色时判为占位图，跳到下一个 rep。
- **JPEG 2000 的容器**：Adobe 那个 bundle 的 `ic08/ic09` 是 `jP` 开头（JPEG 2000），标准库解不了——新增 `icnsPNGViaSips` 用 `/usr/bin/sips` 转一张 256px PNG 兜底，结果同样按 bundle 路径缓存。
- 实测：`/Applications` + `/System/Applications` 全量扫描后**没有 blank 图标**；Adobe CC Cleaner 从「无图」变成 33,481 字节的真图；列表 16 个图标全部 `naturalWidth > 0`，`background: rgba(0,0,0,0)`、`box-shadow: none`、`border-radius: 0px`、`object-fit: contain`。

## 4. 有意没做的

- 没有换掉暖炭底色与陶土主色（这是产品的识别）；没有引入字体文件；没有把单文件前端拆成构建产物。
- 没有给每个模块都做「独立艺术指导」——统一组件语言比逐个美化更能让 app 看起来安静。
- 方块图的色阶仍然偏暖，因为面积图需要让「大块」在小尺寸下也读得出来；这是数据可视化优先于极简的一处例外。
