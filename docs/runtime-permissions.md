# 运行方式、权限与实际功能

## 推荐启动方式

使用 `make run`。它构建并打开 `build/darwin-arm64/MoleStudio.app`，架构按 Go 环境选择；未安装 MyGo CLI 时使用固定版本的构建器。
原先的 `MYGO_FRONTEND_DIST=Resources/src-ui go run .` 保留为 `make run-raw`，只用于临时桥接调试。

临时 Go 程序通常没有绑定 `Info.plist`，签名标识可能为 `a.out`，权限也可能归属启动它的终端。
这不意味着所有扫描函数不存在，但不能当作与应用包相同的权限和菜单栏验收环境。
若旧 `go run` 实例仍运行，先在原终端按 Ctrl-C 再运行新版入口；启动脚本不会自动终止它。

应用仍使用本地临时签名，重建可能改变 macOS 对它的识别。应用包提供明确路径和标识，不保证跨重建永久保留授权；稳定分发签名尚未配置。

## 如何检查权限

主窗口顶部的“权限”打开“运行与权限”，显示当前可执行路径、应用标识、版本、菜单栏是否已注册及受保护目录的实际读取检查。
读取成功只代表探测位置可读，不应当作所有目录均已授权；“未知”不等于已授权。

面板逐项显示完全磁盘访问、桌面、文稿、下载、应用管理与管理员授权，检查时间随结果显示：

| 状态 | 含义 |
| --- | --- |
| 正在检查… | 本次请求尚未返回；已有读取结论单独标为上次证据 |
| 本次未确认 | 未收到本次回执或回执缺少所请求的目录结果；不把历史结论冒充本次检查结果 |
| 已验证可读取 | 当前进程本次目录读取通过，不等于 TCC 系统开关已被查询或全盘已授权 |
| 读取被拒绝 | 读取被系统或目录访问控制拒绝，需核对对应权限和路径；不能单凭这个结果断言开关关闭 |
| 尚未检查 | 未主动核对该目录，不能当作未授权 |
| 尚不能判定 | 读取超时或目录不可用，可能正在等待系统授权；未将缺失结果算作通过 |
| 目录不存在 | 本机未找到这个目录，无法据此判断权限 |
| 无可核验目录 | 完全磁盘访问的探测位置均不存在，无法据此判断该权限是否授予 |
| 需在设置确认 | 应用管理开关未进行安全核验；读到应用不证明允许卸载 |
| 操作时授权 | 管理员授权只在确认维护后单独请求，不是持续授予的权限 |

完全磁盘访问检查分别列举 `~/Library/Mail` 和 `~/Library/Safari`，只返回目录计数、状态和路径，不读取文件内容或 TCC 数据库。一个目录可读不能掩盖另一个目录被拒绝或未能读取；全部现存探测目录可读时，也只显示已验证读取能力。

打开面板和“刷新状态”不会主动探测桌面、文稿、下载。点击“检查目录读取”才分别核对这三个目录，可能触发 macOS 的读取许可提示；使用者可以拒绝。等待时每行显示“正在检查…”，上次结论与实际核对时间单独保留；未收到回执或回执缺少所请求的目录结果时，显示“本次未确认”并提示显式重试。基础刷新不重查这三个目录，也不会解除它们的未确认状态；只有对应的新目录读取回执才能恢复实际结论，旧回执不能覆盖新请求。

核对时间显示完整日期和时间，避免将前一天的证据误认为本次检查。无效或缺失的原生观察时间显示“时间未知”，不伪造新的观察时间。

桌面、文稿、下载未能读取时，具体原因直接显示在对应行，不必悬停才能查看。完全磁盘访问的展开证据逐项显示 Mail / Safari 的读取说明，便于区分目录不存在、访问拒绝和其他读取失败。等待核对时旧说明标为“上次读取说明”，新回执替换旧原因；长路径自动换行，错误文字只作为文本显示，不执行其中的内容。

核对尚未返回时，关闭后重开或重复打开权限入口会继续等待原请求，不再重复读取或重置等待期限。关闭面板不取消已发出的只读核对，回执在后台更新证据但不会重新弹出面板。等待超时后允许重开重试，旧请求回执不能结束新请求；已完成的目录读取结果仍保留，不因重开而再次探测桌面、文稿和下载。

完全磁盘访问的当前核对在等待时显示“正在检查…”，未收到回执后显示“本次未确认”；上次读取结论和原核对时间单独保留。只有新的对应原生回执才能恢复可读取/被拒绝状态，超时不改写历史结论。权限探测使用有界目录读取，但不增删文件扫描的告警记录：一次可读探测不能抹掉未完成的扫描测量，探测失败也不冒充文件扫描失败。

长说明可展开查看，状态行与对应设置入口分开排列；正文可滚动，刷新和关闭按钮保持可见。菜单栏注册单独标注“不是权限开关”，不混入授权结果。

同一应用的刷新保留已展开的读取证据、授权说明和滚动位置，键盘焦点跟随同一个说明入口；Tab 循环包含可展开的摘要。若运行应用的路径或标识变化，清除旧视图并回到顶部显示新身份，不沿用上一应用的目录读取结果。没有核验位置时不显示“查看 0 个目录”；原先聚焦的证据入口消失后，焦点安全返回关闭按钮。

面板另列出最近本机模块扫描中尚未完成读取的路径，按已有目录分组显示原始原因。Mail/Safari 探测可读时，这些扫描告警仍保留；读取上限、超时和普通目录访问控制不改变已测得的权限探测状态，也不表示相同数量的权限开关未授予。正常项目目录的本地访问控制拒绝不推荐完全磁盘访问；只为已识别的受保护目录提供对应设置核对入口，仍不保证授权能解决所有读取问题。

扫描回执会同步更新面板和提示条，保留展开状态、同一目录动作的焦点和滚动。完整的新扫描结果清除已不存在的告警，但不会清除独立核验的读取拒绝；刷新权限状态也不会额外重扫用户目录。长路径中的原始读取错误换行显示，不截掉末尾失败原因。此处是本机模块扫描记录，空间分析自己的受限范围仍在该模块内披露。

- 完全磁盘访问：必须由使用者在系统设置中开启，应用不能自动授予。没有列出应用时，可先在访达显示当前程序，再用“+”添加应用包。
- 文件与文件夹：macOS 在实际访问桌面、文稿和下载目录时请求许可；应用包提供对应用途说明。拒绝后可以从该面板打开对应设置页。
- 应用管理与其他应用数据：读取或移除其他应用的资源可能触发系统限制。卸载只提交明确预览并确认的路径；不会通过删除文件来测试权限。
- 菜单栏：图标可能被系统设置或刘海区域隐藏。主窗口“菜单栏”按钮和原生“工具 → 菜单栏工具”提供另一条入口。

授权后退出并重新打开应用，再重新扫描或主动核对目录读取。程序不会自动修改 TCC 数据库、重置已有授权或申请不需要的摄像头、麦克风等权限。

## 菜单栏图表与快速清理

菜单栏显示 CPU 的 0–100% 趋势、共用刻度的下载/上传曲线、内存分项容量条和磁盘使用条。趋势只保留最近 40 次真实显示采样；首个样本不画成历史曲线，缺失来源不补零。磁盘容量由遥测直接提供，不必等待文件扫描。

内存条区分应用、系统固定、压缩与剩余容量；文件缓存包含在剩余容量中，不再额外加成一段。用量采用内核页计数，内存单位为 GiB；原生内存压力是独立的正常/偏高/很高状态，不用占用比例猜测。进程 CPU 以一个核心为 100%，与整机 CPU 图表的 0–100% 口径不同。

“快速清理…”在主窗口打开当前所选缓存的精确路径确认。没有扫描结果或没有勾选时不会执行；确认集合冻结，后续刷新不能添加路径。按钮不显示另一页面的“已选容量”，以免把菜单栏快照当成主窗口当前选择。

### 可选的系统文件缓存释放

“内存管理…”先显示实际内存分项、原生压力与风险，再提供“授权并释放文件缓存”。它只通过 macOS 的 `osascript` 管理员授权执行固定 `/usr/sbin/purge`；应用不读取密码，不静默运行 `sudo`。

`purge` 是磁盘文件缓存释放工具，不会清空 `malloc`/`vm_allocate` 分配的应用内存。它不是解决内存泄漏或提高 CPU 性能的功能；macOS 会自行回收可用缓存，压力正常时通常无需操作。缓存重建可能暂时降低读文件性能，显示的文件缓存量也不是本次预计释放量。

请求必须明确确认并携带标识。前端和原生端都阻止重叠，原生重复标识不发送假完成回执；成功、授权取消、失败与状态未知分别呈现。授权/命令超过等待期限可能仍在系统侧运行，界面不会宣称已停止，也不自动重试；本次应用会话内拒绝再次释放，需先核对活动监视器中的 `purge`。关闭说明面板不取消已经提交的系统命令。

图表与入口参考 [iStat Menus](https://bjango.com/mac/istatmenus/)、[CleanMyMac Menu](https://macpaw.com/support/cleanmymac/knowledgebase/cleanmymac-menu)；内存分项核对 [Stats RAM 读取源码](https://github.com/exelban/stats/blob/master/Modules/RAM/readers.swift) 和 [Apple 活动监视器说明](https://support.apple.com/guide/activity-monitor/view-memory-usage-actmntr1004/mac)。命令边界依据本机 `man purge`，没有复制商业产品的“释放应用 RAM”或加速宣传。

## 启动扫描与等待

应用启动后会自动进行只读扫描。深度清理、AI 清理、应用卸载和构建清理在原生扫描开始时显示“正在扫描”及列表占位，不再把尚未返回的结果显示为没有候选。

刷新期间保留原列表供查看，但旧测量不能打开新的清理预览。扫描超过 20 秒只提示继续等待，不宣称失败，也不会再次提交扫描；实际回执返回后才恢复预览和刷新控件。空回执不能结束等待。

“预览所选”不可点击还可能是尚未勾选、候选受保护或测量不完整。可以检查具体子路径；不要为了使按钮可用而解除保护。若扫描始终没有返回，可正常退出并重新打开应用，不要反复提交。

## 应用卸载入口

“应用卸载”默认显示“已安装应用”，不再因没有残留而隐藏已有应用；“已卸载残留”仍是独立可切换的面板。进入列表不会自动勾选应用。

尚未扫描时，侧栏显示“待扫描”而不是“0 应用”；两个面板的“开始扫描”都只请求一次真实只读扫描。完成扫描后如没有候选，“预览所选”保持禁用，不将空结果当作尚未启动扫描。

## 当前实现范围

| 模块 | 真实接入 | 边界 |
| --- | --- | --- |
| 深度清理 | 缓存、日志及常见浏览器/开发工具目录扫描，所选路径移入废纸篓与回执 | 不是任意系统文件清理；运行中、受保护及未完成测量的路径不可默认删除 |
| AI 清理 | 按工具识别可重建缓存、旧诊断文件及可核验旧版本，执行前复核路径/进程/打开文件 | 会话、任务历史、模型、工作树与凭据只读保留；默认路径覆盖不等于所有 AI 产品均已覆盖 |
| 应用卸载 | 已安装应用和残留扫描，按应用/缓存/配置选择移除 | 系统保护和应用管理许可可能限制操作；不保证识别全部第三方残留 |
| 系统加速 | Quick Look 缩略图缓存重建，等待原生命令回执 | 此模块仍只有缩略图维护；菜单栏独立提供可选文件缓存释放，没有清空应用 RAM、CPU 加速或风扇控制 |
| 构建清理 | 可重建产物与安装包扫描，预览选择后移入废纸篓 | 有范围和读取上限；运行中的构建任务受保护 |

源码与测试证明这些链路并非空壳，不等于全部模块已达到成熟商业产品的覆盖度。
空列表也可能来自没有候选项、权限拒绝、正在扫描、未读取或保护规则，应查看本次扫描的具体状态。

## 清理容量与扫描覆盖

深度清理把“已测量”“可审查”和“保留（已测）”分开显示，不再让未勾选时的 `0 B` 看起来像没有缓存。“可审查”只统计完整测量且不受保护的路径，并不自动勾选，也不是本次必然释放的容量；确认仍冻结具体路径，执行时再次核对运行状态与保护规则。

本模块已识别但被白名单或核心保护整个排除的扫描目录单独披露，显示准确路径、原因及“体积未测量”。不额外遍历这些目录来填充数字，不把它们加回候选；“查看白名单”只打开已有规则，不直接移除任何规则。新扫描回执会替换排除证据，不能沿用缺失的旧结果。

缓存根目录及其子目录的文件测量预算提高到每处 100,000 个普通文件，保留每目录 5 秒期限与读取拒绝处理。超过预算、超时或未完整读取的路径仍保留，不因为扩充预算而默认删除。应用包、残留和安装包各自的预算没有改变；没有增加新的扫描来源。

白名单中整个目录的保护优先于较早出现的子项规则，规则顺序不能把整根排除误报成仅保护部分子项。此处修正判断逻辑，不改写使用者的白名单文件。

macOS 下白名单匹配保守地忽略路径大小写，避免同一个 APFS 目录因换一种写法而绕过精确路径、父目录、通配符或复合规则。显示和保存的规则仍保留原写法，不改写白名单文件。对于区分大小写的 macOS 卷，这可能额外保护仅大小写不同的另一条路径；不会为了增加可清理容量而放松保护。

## AI／Agent 数据清理

AI 清理按“工具”和“数据类型”组织结果。顶部区分已测量、可审查和保留容量，工具筛选只列出本次识别的资源；只有被白名单排除的已识别缓存也会计入工具覆盖，但其未测量体积不加入容量。首次扫描与工具运行时都不会自动勾选新增数据。

测量容量、类别数量和白名单排除证据使用当前工具与关键词范围；类别按钮的数量仍表示该范围内各类结果，不把其他工具的数据混入统计。只存在排除证据的工具也有明确空列表原因，不能被其他工具的候选遮掩。

“全部已选待移入废纸篓”是整个 AI 模块的现有选择，不随显示筛选偷偷删改。已选路径被工具、类别或关键词隐藏时，面板列出筛选外的路径数量与容量，明确预览包含全部已选。“显示全部”只清除显示筛选，保留原选择，焦点返回工具选择框；排除控件增删和回执更新不再把工具筛选的焦点移到其他操作。

| 数据类型 | 已识别的默认来源 | 处理方式 |
| --- | --- | --- |
| 可重建缓存 | Codex、Claude Desktop、Cursor／Cursor Agent、Windsurf、ChatGPT、LM Studio 的已识别系统缓存及 `Cache`、`Code Cache`、`GPUCache` 等明确子目录 | 闲置、完整测量且不被白名单保护时可选择；不移除整个 Application Support、Cookies、IndexedDB 或 Local Storage |
| 诊断日志 | Codex 的 `~/.codex/log`、Claude Code 的 `~/.claude/debug`、Copilot CLI 的 `~/.copilot/logs`、OpenCode 的 `~/.local/share/opencode/log`、Claude Desktop 的 `~/Library/Logs/Claude` | 只选择直接子项中的普通 `.log` 文件，Claude Code 另识别 `.txt` 诊断文件；不递归清空整个日志根目录 |
| 程序旧版本 | 原有 Claude Code、Cursor Agent、Copilot CLI、Claude Desktop 的已知版本目录 | 保留启动器当前版本和备用版本，处理前重新核对启动器、进程与文件句柄 |
| 会话与任务资料 | 已知 Codex、Claude、Copilot、OpenCode、Gemini、Windsurf、Continue、Cline、Roo Code、Copilot Chat 的会话、附件、文件历史、快照或索引位置 | 仅测量，不读取正文，不提供移除选择；数据库和未合并工作成果不能按日志处理 |
| 模型、扩展与工作树 | 原有 Cursor 扩展、Codex／Cursor 工作树，以及 Hugging Face、Ollama、LM Studio 的已知模型目录 | 只读保留，由原工具核对引用关系或管理 |

诊断日志保留最近 30 天、目录中最新的一份、`latest` 指向的文件、运行中工具的数据、仍被打开及硬链接共享的文件；状态不明也保留。每个日志根目录最多展示 40 份诊断文件，超过上限明确报告；超过 1000 个目录项时不授予日志清理资格。这里按修改时间保护最近写入，并不据此推断会话已经结束。

缓存会重新生成，旧诊断内容则无法重建；移除日志会失去相应历史排障信息。所有新增项默认不选，确认只冻结实际选择的子目录或日志文件，执行时使用共享保护检查再次核对。路径、文件数量、修改时间和占用来自本地元数据，不会读取凭据、会话正文或上传文件内容。

仅覆盖默认路径；`CODEX_HOME`、Codex 的 `log_dir`、Copilot 的自定义配置目录、XDG 路径、其他编辑器配置档及未知工具不自动推断。OpenCode 的 `opencode.db`、WAL、快照和 `.cache/opencode/bin` 不属于本轮可删除日志；Gemini 的 `tmp` 可能包含会话，不能因为名字叫临时目录就清空。白名单依然优先，识别出缓存不等于获准删除。

来源核对：[OpenAI Codex 配置参考](https://developers.openai.com/codex/config-reference/) 将 `log_dir` 与历史、SQLite 状态分开；[GitHub Copilot CLI 目录参考](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-config-dir-reference) 将 `logs/` 与会话、插件和凭据分开；[Electron 应用目录说明](https://www.electronjs.org/docs/latest/api/app) 明确同一应用目录可同时包含缓存、Cookies 与 Local Storage。Claude Code 和 OpenCode 的部分诊断位置通过本机目录元数据核对，未声称其所有版本均采用相同路径。

## 构建目录的识别边界

构建清理只搜索 `~/Projects`、`~/GitHub`、`~/Developer`、`~/code` 和 `~/src`，不扫描任意磁盘位置。普通源码文件不消耗目录探索预算；每个根目录最多探索 4000 个目录，达到上限仍报告未完成范围，不保证列出全部工程。

只将已识别的目录名作为候选，名为 `target`、`build` 等的普通文件不作为构建目录。完整测量且不少于 20 MB 的候选，以及测量不完整的目录，按体积排序后最多显示 20 项；名称本身不能证明可删除。运行中的工具、白名单和未完成测量的路径继续保留，候选不会自动勾选。

## 验收

`make check` 覆盖扫描器、保护规则、回执和启动脚本；`make test-ui-webkit` 验证界面交互。
视觉验收不会在真实用户目录执行清理、卸载或还原；这些操作仍需要用户确认。
管理员授权与实际 `purge` 不作为自动验收步骤；命令、同意门槛和回执状态使用隔离测试，不能当作已在这台 Mac 执行缓存释放。
